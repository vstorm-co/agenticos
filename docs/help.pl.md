# Pomoc i współtworzenie { #get-help-and-contribute }

Błędy odtwarzalne zgłaszaj przez [szablony issues](https://github.com/vstorm-co/agenticos/issues/new/choose), po sprawdzeniu istniejących zgłoszeń. Podaj wydanie lub commit, typ wdrożenia, model i narzędzia, oczekiwany i rzeczywisty wynik oraz minimalne syntetyczne wejście.

Nie dołączaj kluczy ani prywatnych dokumentów. Podejrzenie podatności zgłoś prywatnie według [SECURITY.md](https://github.com/vstorm-co/agenticos/blob/main/SECURITY.md), zamiast publikować reprodukcję.

## Przed zgłoszeniem problemu instalacji { #before-reporting-an-installation-problem }

Sprawdź [instalację](install.md) i [konfigurację wdrożenia](deployment.md). Zapisz polecenie i błąd bez danych prywatnych. Przy odpowiedziach dokumentowych sprawdź przetwarzanie, kolekcję i uprawnienia. Przy błędzie narzędzia zachowaj komunikat i status runu. Test połączenia nie dowodzi wykonania zadania.

## Wkład w projekt lub pomoc wdrożeniowa { #contribute-or-scope-implementation-help }

Przed zmianą działania przeczytaj [CONTRIBUTING.md](https://github.com/vstorm-co/agenticos/blob/main/CONTRIBUTING.md), [architekturę](architecture.md) i właściwy poradnik. Konkretna poprawka dokumentacji lub odtwarzalny błąd to wartościowy wkład. Większe zmiany uzgodnij z maintainerami w repozytorium.

W sprawie wdrożenia, dokumentacji, procesów i rozwoju customowego skontaktuj się z [Vstorm](https://vstorm.co/) lub Kacprem. Zobowiązania wsparcia ustala się osobno. Publiczne issues nie są kontraktowym SLA.
