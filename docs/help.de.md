# Hilfe und Beiträge { #get-help-and-contribute }

Melden Sie reproduzierbare Fehler über die [Issue-Vorlagen](https://github.com/vstorm-co/agenticos/issues/new/choose), nachdem Sie vorhandene Meldungen geprüft haben. Nennen Sie Release oder Commit, Deployment-Typ, Modell und Werkzeuge, erwartetes und tatsächliches Ergebnis sowie eine minimale synthetische Eingabe.

Fügen Sie keine Zugangsdaten oder privaten Dokumente hinzu. Melden Sie vermutete Sicherheitslücken privat gemäß [SECURITY.md](https://github.com/vstorm-co/agenticos/blob/main/SECURITY.md), nicht als öffentliche Reproduktion.

## Vor einer Installationsmeldung { #before-reporting-an-installation-problem }

Prüfen Sie [Installation](install.md) und [Deployment-Konfiguration](deployment.md). Erfassen Sie den fehlgeschlagenen Befehl und einen bereinigten Fehler. Prüfen Sie bei Dokumentenantworten Verarbeitung, Bindung und Berechtigungen. Bewahren Sie bei Werkzeugfehlern Meldung und Run-Status auf. Ein Verbindungstest beweist keine Aufgabenerledigung.

## Beitragen oder Implementierungshilfe vereinbaren { #contribute-or-scope-implementation-help }

Lesen Sie vor Verhaltensänderungen [CONTRIBUTING.md](https://github.com/vstorm-co/agenticos/blob/main/CONTRIBUTING.md), [Architektur](architecture.md) und die passende Anleitung. Eine fokussierte Dokumentationskorrektur oder reproduzierbare Meldung ist hilfreich. Stimmen Sie größere Änderungen mit Maintainern im Repository ab.

Kontaktieren Sie [Vstorm](https://vstorm.co/) oder Kacper für Kundeninfrastruktur, Dokumentation, Prozesse und individuelle Entwicklung. Supportzusagen werden separat vereinbart. Community-Issues sind kein vertragliches Antwort-SLA.
