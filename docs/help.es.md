# Ayuda y contribuciones { #get-help-and-contribute }

Comunica fallos reproducibles mediante las [plantillas de issues](https://github.com/vstorm-co/agenticos/issues/new/choose), tras buscar incidencias existentes. Incluye versión o commit, tipo de despliegue, modelo y herramientas, resultado esperado y real, y una entrada sintética mínima.

No incluyas credenciales ni documentos privados. Comunica vulnerabilidades en privado siguiendo [SECURITY.md](https://github.com/vstorm-co/agenticos/blob/main/SECURITY.md), no mediante una reproducción pública.

## Antes de informar de un problema de instalación { #before-reporting-an-installation-problem }

Revisa [instalación](install.md) y [configuración](deployment.md). Guarda el comando fallido y el error sin datos privados. Para respuestas documentales, comprueba procesamiento, colección y permisos. Para herramientas, conserva error y estado del run. Una prueba de conexión no demuestra que la tarea terminó.

## Contribuye o acuerda ayuda de implementación { #contribute-or-scope-implementation-help }

Antes de cambiar comportamiento, lee [CONTRIBUTING.md](https://github.com/vstorm-co/agenticos/blob/main/CONTRIBUTING.md), [arquitectura](architecture.md) y la guía pertinente. Una corrección documental concreta o una incidencia reproducible son contribuciones útiles. Coordina cambios mayores con los maintainers en el repositorio.

Para infraestructura del cliente, documentación, procesos y desarrollo personalizado, contacta con [Vstorm](https://vstorm.co/) o Kacper. Los compromisos de soporte se acuerdan aparte. Los issues comunitarios no son un SLA contractual.
