# AgenticOS vs Dify { #agenticos-vs-dify }

Self-Hosting und Dokumenten-Retrieval sind gemeinsame Möglichkeiten. Entscheidend ist, wie Ihr Team eine konkrete Aufgabe erstellt, verändert und betreibt.

Verantwortlich: AgenticOS-Team. Quellen geprüft am 25. September 2026. AgenticOS: v0.0.503. Dify: öffentliches Repository und Lizenz, kein getesteter Cloud-Tarif oder festgelegtes Deployment.

## Dokumentierte Ausgangspunkte { #documented-starting-points }

| Bereich | Dify | AgenticOS |
| --- | --- | --- |
| Erstellung | Visuelle Workflows, Agents und RAG | Browser-Instruktionen, Werkzeuge, Sammlungen und veröffentlichte Versionen |
| Bereitstellung | Docker-Self-Hosting dokumentiert | Betreiberverwaltete Bereitstellung dokumentiert |
| Lizenz | Dify Open Source License mit zusätzlichen Bedingungen | Apache-2.0 für das Projekt; Komponentenlizenzen separat prüfen |

Siehe [Dify-Repository](https://github.com/langgenius/dify), [Lizenz](https://github.com/langgenius/dify/blob/main/LICENSE), [AgenticOS-Anleitung](../first-agent.md) und [Lizenzinventar](../licenses.md). Self-Hosting bedeutet keine identischen Lizenzen oder Editionsfunktionen.

## Eine Änderung statt nur einer Antwort vergleichen { #compare-a-change-not-only-an-answer }

Nutzen Sie dasselbe [synthetische Handbuch](../howto/first-document-agent.md), dieselben Fragen und Prüfkriterien. Erfassen Sie Version, Modell, Quellenverarbeitung und Identität auf beiden Seiten. Ändern Sie die zuständige Person und wiederholen Sie nach der Verarbeitung.

Dify ist ein Kandidat, wenn visuelle Workflows zur Prozessbeschreibung Ihres Teams passen. AgenticOS ist ein Kandidat, wenn das Konfigurieren und Veröffentlichen von Agents mit Instruktionen, Werkzeugen und Sammlungen passt. Prüfen Sie Anforderungen in der konkreten Edition.

Kein direkter Ausführungstest, Qualitätsranking oder Vergleich der Wartungszeit wird berichtet. Unbekanntes bleibt offen. Nutzen Sie [Vergleichsmethode](comparison.md) und [Betriebscheckliste](../rollout.md).
