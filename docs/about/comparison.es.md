## Una prueba común { #a-shared-trial }

Usa el [mismo documento de ejemplo](../howto/first-document-agent.md) en ambos productos. Haz la pregunta con respuesta y la de la política ausente. Cambia el responsable, procesa la fuente y repite. Conserva las respuestas, la configuración y los fallos.

Registra versión o plan, modelo, procesamiento de fuentes, identidad, acceso a herramientas, aprobaciones, canal, coste y responsable de operación. Empieza solo con recuperación de información. Si necesitas una acción de herramienta, define antes una operación de prueba inocua y su aprobación esperada.

## Qué demuestra la evidencia { #what-the-evidence-means }

Cada guía indica fuentes y fecha. La descripción del proveedor acredita una opción documentada, no su calidad para tu tarea. No se ha probado ninguna cuenta de competidores. El comportamiento no probado queda como desconocido, no como una función ausente.

Al publicar una prueba, incluye entradas exactas, resultados reales, fallos y configuración. Separa el consumo de modelos de infraestructura, implementación y operación. Revisa [licencias](../licenses.md), condiciones y edición.

## Otros puntos de partida { #other-starting-points }

Una biblioteca como [Pydantic AI](https://ai.pydantic.dev/) encaja con un agent dentro de tu aplicación. AgenticOS añade una aplicación para configurar y operar agents. [n8n](https://n8n.io/) incluye workflows y agents de IA. [OpenClaw](https://github.com/openclaw/openclaw) documenta despliegues personales y compartidos. [Lindy](https://www.lindy.ai/) ofrece un servicio de asistente. Son candidatos adicionales, no productos descartados.

Empieza con la [tarea documental](../howto/first-document-agent.md) y revisa la [operación e implementación](../rollout.md). Los maintainers de AgenticOS mantienen estas guías. Fuentes comprobadas el 25 de septiembre de 2026; revisar antes del 25 de octubre de 2026 o cuando cambie la oferta.
