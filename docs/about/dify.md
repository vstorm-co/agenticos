# AgenticOS vs Dify

Self-hosting and document retrieval are shared ground. Choose between AgenticOS and Dify by how your team builds, changes and operates a particular task.

Maintained by the AgenticOS team. Sources checked 25 September 2026. AgenticOS baseline: v0.0.503. Dify scope: public repository and licence, not a tested cloud plan or pinned deployment.

## Documented starting points

| Area | Dify | AgenticOS |
| --- | --- | --- |
| Building | Visual workflows, agents and RAG | Browser instructions, selected tools, collections and published agent versions |
| Deployment | Docker self-hosting is documented | Operator-managed deployment is documented |
| Licence | Dify Open Source License includes additional conditions | Project uses Apache-2.0; review component licences separately |

See [Dify's repository](https://github.com/langgenius/dify) and [licence](https://github.com/langgenius/dify/blob/main/LICENSE), and AgenticOS [first-agent instructions](../first-agent.md) and [licence inventory](../licenses.md). Do not infer identical licensing or edition features from the phrase self-hosted.

## Compare a change, not only an answer

Use the same [synthetic handbook](../howto/first-document-agent.md), questions and reference checks. Record the version, model, source-processing settings and identity on each side. Then change the request owner in the source and repeat after processing.

Dify is a candidate when its visual workflow approach matches how your team wants to express the process. AgenticOS is a candidate when configuring and publishing agents around instructions, tools and collections matches your operating process. Test required capabilities in the exact edition you would deploy.

No side-by-side execution, quality ranking or maintenance-time comparison is reported. Unknown requirements stay open. Use the [comparison method](comparison.md) and [operating checklist](../rollout.md) before choosing.
