# Wybierz pierwsze zadanie { #choose-a-first-task }

Zacznij od pracy, której wynik ktoś w zespole potrafi ocenić. Każdy poniższy tutorial daje Ci syntetyczne dane wejściowe, konfigurację, dokładny prompt, kryteria sprawdzenia, typowe błędy i listę tego, co zapisać. To punkty startu z referencyjnymi runami, nie historie klientów ani deklaracje skuteczności.

| Zadanie | Wejście i wynik | Tutorial | Ostatni run wykonany przez opiekunów projektu |
| --- | --- | --- | --- |
| Odpowiedz na pytanie z handbooka | Dokument i pytanie dają odpowiedź opartą na źródle | [Zbuduj pierwszego agenta z dokumentem](howto/first-document-agent.md) | Jeszcze nie zapisany |
| Odpowiedz w Slacku | Ten sam agent odpowiada w wątku Slacka, a run pokazuje, kto pytał | [Odpowiedz na pytanie z handbooka w Slacku](howto/slack-handbook-assistant.md) | Jeszcze nie zapisany |
| Zamień CSV na wykres | Plik i sandbox dają sumy, wykres, skrypt i plik PNG | [Zamień CSV na wykres, który możesz sprawdzić](howto/csv-chart.md) | v0.0.504, 25 września 2026 |
| Zaplanuj cotygodniowy raport | Samowystarczalne zadanie daje wersjonowany raport według harmonogramu | [Zaplanuj cotygodniowy raport](howto/scheduled-report.md) | v0.0.504, 25 września 2026 |
| Przygotuj szkic zgłoszenia sprzętu | Dostarczone fakty i spisana procedura dają szkic do sprawdzenia | Powiąż [knowledge i skill](skills.md); sprawdź brakujące pola, zanim dodasz jakiekolwiek narzędzie wysyłki | Jeszcze bez tutoriala |

Zapisany run pokazuje, co zrobiła jedna konfiguracja jednego dnia, z jednym modelem. Nie dowodzi, że Twoja konfiguracja przejdzie te same sprawdzenia. Szczegóły są w tutorialu. Trzymaj razem własne dane wejściowe, rzeczywisty wynik, run i błędy.

Istniejące [ekrany i nagrania](screens.md) pokazują interfejs produktu. One również nie są dowodem tych sprawdzeń.

Wybierz jeden punkt wejścia spośród [kanałów](channels.md), a potem przypisz odpowiedzialność za [utrzymanie](rollout.md). Jeśli dopiero wybierasz platformę, skorzystaj z [porównań](about/comparison.md).
