# Choose a first task

Start with work whose result someone on the team can judge. Each tutorial below gives you a synthetic input, the configuration, the exact prompt, reference checks, the usual failures and what to record. They are starting points with reference runs, not customer case studies or success-rate claims.

| Task | Input and output | Tutorial | Last run by the maintainers |
| --- | --- | --- | --- |
| Answer a handbook question | A document and a question produce a source-backed answer | [Build your first document agent](howto/first-document-agent.md) | Not yet recorded |
| Answer it in Slack | The same agent answers in a Slack thread, and the run shows who asked | [Answer a handbook question in Slack](howto/slack-handbook-assistant.md) | Not yet recorded |
| Turn a CSV into a chart | A file and a sandbox produce totals, a chart, a script and a PNG | [Turn a CSV into a chart you can check](howto/csv-chart.md) | v0.0.504, 25 September 2026 |
| Schedule a weekly report | A self-contained task produces a versioned report on a schedule | [Schedule a weekly report](howto/scheduled-report.md) | v0.0.504, 25 September 2026 |
| Draft an equipment request | Supplied facts and a written procedure produce a handoff for review | Bind [knowledge and a skill](skills.md); check missing fields before adding any submission tool | No tutorial yet |

A recorded run shows what one configuration did on one date, with one model. It is not evidence that your configuration passes the same checks. The tutorial carries the details. Keep your own input, actual output, run and errors together.

The existing [screens and recordings](screens.md) show product interfaces. They are not evidence of these checks either.

Choose one entry point through [channels](channels.md), then assign responsibility for [operation](rollout.md). If you are still selecting a platform, use the [comparisons](about/comparison.md).
