# Context file starter

## Scope and maintenance

- Audience: the narrowest project or organization team that actually uses this knowledge.
- Owner: the role responsible for maintaining the material.
- Review trigger: a change to the documented process, source or terminology.

## Standing facts

Define the relevant terms; include a verified link to the system of record for each fact that can change. For example, the release board owns delivery dates; the incident log owns the timeline. Spell out which source wins and what to do when a record is missing.

## Load strategy

Use compact injected context for facts required on most runs. Put larger supporting documents on demand. Keep private preferences in personal memory and changing work in live records. An AGENTS.md in a project is useful for repository-specific work; it is not a reason to copy its full content into an organization-wide file or to widen access.

## Verification

Ask one question with different plausible answers in different scopes, then one for which the source lacks an answer. Verify the correct scope and link, and that the assistant acknowledges the missing fact. Check that the intended agent actually has the Context binding.
