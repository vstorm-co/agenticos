# Turn proven work into a skill

1. Identify the repeated decision, the inputs and a recognizable finished product. Search skills first and inspect the nearest match.
2. Agree who owns it and where it applies. A title and description should help a future agent choose this skill and skip close but irrelevant requests.
3. Put stable decisions and stop conditions in the body. Move optional examples and templates into resources named by the decision they help with. Test resource links after saving.
4. Use the platform's skill tools to create or update the skill and add resources. Bind it only to the intended agents. Saving a skill does not publish an agent draft.

## Example

A team reviews a release report each week. The steps for reconciling changelog and release tags are a skill. The release channels and source priorities are Context. This week's release observations are live records. A recurring review is a routine.

## Verify

Run a representative release with two artifact formats, a routine status question that should skip the skill, and a changelog with conflicting versions. A pass leaves one evidence-backed report with the active release link and labels unresolved versions. Check that replacing a skill updates the intended copy while other agents retain their versions.
