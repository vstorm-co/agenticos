# Projects

This author-controlled capability finds projects and exposes their existing shared
file store without requiring Sandbox or a command executor. Selection is run-local
and separate from command targeting. It opens no runtime, copies no private files,
and never borrows the default project's agent or linked resources' authority.

The runner supplies a narrow port. Every operation refreshes the original member,
project access, active workspace generation and routine source ceiling. Unknown
room audiences and unrelated shared transcripts cannot discover or read projects;
a linked private channel conversation follows the same path as private web chat.
Approval continuations restore selection and command target, then recheck access.

Stored-file projects support text work; service projects use their configured
runtime for an explicit file operation. Large, unknown-size and non-UTF-8 files
are refused by the text reader. Existing storage, capacity and persistence rules
remain authoritative. There is no new versioned file store or background sync.

Read tools are read-only; writes retain normal approval policy. Projects requires
`projects:read` and `projects:write` capability scopes, independently of live
resource permission checks. It never supplies shell execution. Sandbox's explicit
command target selection is needed to execute against a project's service runtime.
